Multica 使用你自己的 Slack app。连接后，团队成员可以私聊 Bot、在频道里 @ 它，或用 `/issue` 创建 issue。

一个 Slack app 对应一个 Multica 智能体。需要接入多个智能体时，为每个智能体分别创建 app。

## 开始前

连接需要工作区 owner 或 admin 完成，最终把两个凭据填入 Multica：

- Bot User OAuth Token，以 `xoxb-` 开头；
- App-level Token，以 `xapp-` 开头。

## 1. 从 manifest 创建 Slack app

打开 [Slack API Apps](https://api.slack.com/apps)，点击 **Create New App → From a manifest**，选择 Slack workspace，然后在 **YAML** 中粘贴以下内容：

```yaml
display_information:
  name: Multica
features:
  app_home:
    home_tab_enabled: false
    messages_tab_enabled: true
    messages_tab_read_only_enabled: false
  bot_user:
    display_name: Multica
    always_online: true
  slash_commands:
    - command: /issue
      description: Create a Multica issue
      usage_hint: "[description]"
oauth_config:
  scopes:
    bot:
      - app_mentions:read
      - channels:history
      - files:read
      - groups:history
      - im:history
      - mpim:history
      - chat:write
      - reactions:write
      - users:read
      - commands
settings:
  event_subscriptions:
    bot_events:
      - app_mention
      - message.im
      - message.channels
      - message.groups
      - message.mpim
  interactivity:
    is_enabled: false
  org_deploy_enabled: false
  socket_mode_enabled: true
  token_rotation_enabled: false
```

创建前可以把两个 `Multica` 改成智能体的名字。不要删除 manifest 中的权限或事件，否则私聊、频道提及、回复或 `/issue` 可能无法工作。

<Callout type="warning">
如果这个 Slack app 是在附件支持上线前安装的，请添加 `files:read` Bot scope，并将 app 重新安装到 workspace。在重新安装 app 前，新增 scope 不会应用到现有 Bot token。
</Callout>

Bot 使用 Socket Mode 主动连接 Slack，不需要配置公网 Request URL 或 OAuth Redirect URL。

## 2. 获取两个 token

### Bot token

1. 在 Slack app 中打开 **Install App**。
2. 点击 **Install to Workspace** 并批准权限。
3. 复制 **Bot User OAuth Token**，它以 `xoxb-` 开头。


### App-level token

1. 打开 **Basic Information → App-Level Tokens**。
2. 点击 **Generate Token and Scopes**。
3. 添加 `connections:write` scope。
4. 生成并复制以 `xapp-` 开头的 token。


## 3. 连接到智能体

1. 在 Multica 中打开 **智能体**，选择要接入 Slack 的智能体。
2. 进入 **集成**，点击 **连接 Slack**。
3. 填入 Bot token 和 App-level token。
4. 点击 **连接**。

Multica 会验证两个 token 是否来自同一个 app。连接成功后，页面会显示 **已连接到 Slack**。

<Callout type="warning">
两个 token 会加密保存在 Multica 服务器上。Token 即凭据，不要写进 issue、评论或代码仓库。已连接到其他智能体或工作区的 app 不能直接重复使用，需先断开原连接。
</Callout>

## 第一次使用

成员第一次私聊或 @ Bot 时，会收到一个账号绑定链接。用该工作区的 Multica 账号登录后，再回到 Slack 发送消息。

在频道和群聊中，该链接以私密方式发送：只有发消息的人能看到，会话里不会留下任何内容。不属于该 Multica 工作区的人可以拿到链接，但无法完成绑定；Bot 对同一个人每天最多回应一次。

链接只能使用一次，并会在 15 分钟后过期。过期后再给 Bot 发一条消息即可获得新链接。同一 Multica 工作区中的多个 Bot 如果来自同一个 Slack workspace，通常可以复用已有绑定。

只有当前 Multica 工作区的成员可以使用 Bot。

## 在 Slack 中交代工作

### 私聊

从 Slack 侧栏的 **Apps** 打开 Bot，直接发送消息，不需要 @。

### 频道和群聊

先运行 `/invite @your-bot` 把 Bot 加入频道，再发送 `@your-bot 你的要求`。每个 thread 会形成独立会话；追问时继续在原 thread 中 @ Bot。

Bot 只会响应明确 @ 它的频道消息。执行时，它会在权限允许的范围内读取该 thread 的近期上下文。

### 发送文件

在私聊里，或者在 @ 提及 Bot 的频道消息里直接带上文件。文件会作为附件进入同一项工作，智能体可以结合文件和你的诉求一起处理。

这需要 `files:read` 权限 —— 如果这个应用是在附件支持之前安装的，参考第 1 步的提示。单个文件不超过 20 MiB，一条消息最多带 10 个。超出大小、仍在上传，或者存放在 Slack 之外（比如 Google Drive、Dropbox 链接）的文件会被跳过，消息文本仍然会交给智能体。

### 用 `/issue` 创建 issue

在频道或私聊中输入：

```text
/issue Safari 登录成功后仍然停留在登录页
```

这条命令不需要 @ Bot。Multica 会把描述交给当前 Bot 对应的智能体，由它整理标题和正文并创建 issue。Slack 会先显示一条仅你可见的接收提示；创建完成后，你会在 Multica 收件箱中收到通知。

## 限制 Bot 服务的人和场景

默认情况下，只要发送者已绑定账号且是该 Multica 工作区的成员，Bot 就会在任何被邀请进入的会话中提供服务。对多数团队来说这已经足够：外部人员可以给 Bot 发消息，但拿不到任何结果。

当 Bot 的回复本身涉及敏感内容时，这就不够了。Bot 说的每一句话，会话里的所有人都能看到，因此在人数众多的频道里回复一位已授权成员，或者在含有一位访客的群聊中回复，都等于把这条回复公开给了所有人。

把安装的 chat gate 设为 `members_only`，即可在校验发送者之外同时校验会话：

这两份列表回答的是不同的问题，彼此不重叠：`auth_channel_id` 决定**谁**可以使用 Bot，`allowed_channel_ids` 决定 Bot 在**哪里**工作。持有名单并不会让那个频道自动成为 Bot 应答的场所——如果你也想在那里和 Bot 对话，请把它同时写进两处。

| 会话类型 | 服务条件 |
| --- | --- |
| 私聊 | 发送者已绑定，且仍是工作区成员。 |
| 群聊（多人私聊） | 每一位非 Bot 参与者都已绑定，且仍是工作区成员。只要有一位外部人员，整个会话即关闭，即使发送者已授权。 |
| 频道 | 发送者已授权，**并且**该频道 ID 出现在这个安装的允许频道列表中。 |

被关闭的会话只消耗一次成员查询，不产生任何其他开销：没有会话记录，没有智能体执行，也没有模型用量。Bot 会私下告知发送者此处不可用，其他人看不到任何内容。

设置方式：

```http
PUT /api/workspaces/{workspace_id}/slack/installations/{installation_id}/access
```

```json
{
  "chat_gate": "members_only",
  "auth_channel_id": "G0123456789",
  "refusal_text": "Not an authorized operator",
  "allowed_channel_ids": ["C0123456789"]
}
```

不在名单上的人，无论在哪里发言，都会私下收到相应提示。可以用 `refusal_text` 自定义措辞，留空则使用一段刻意不透露信息的默认文案。已经在名单上、但在 Bot 不工作的频道里发言的人，收到的是另一条指明地点的提示，让他们知道该换个地方，而不是去申请权限。

仅工作区 owner 和 admin 可调用。请求体表示**完整**策略：省略某个字段等于清空它，而不是保留原值。当前策略也会随 `GET /slack/installations` 一起返回。

不填 `allowed_channel_ids`，则 Bot 只在私聊和已授权的群聊中可用。频道 ID 区分大小写。

### 用一个 Slack 频道作为名单

填写 `auth_channel_id` 后，一个私有 Slack 频道的成员列表就是授权名单。要授予权限，把人邀请进该频道；要收回权限，把人移出。不需要修改任何文件，也不需要重新部署，而且名单就在 Slack 里，维护它的人随时能看到。

该频道只会收窄已有规则，不会放宽。使用者仍然必须绑定过 Slack 账号，并且仍然是该 Multica 工作区的成员；频道决定的是这些成员中哪些人在范围内。进入频道并不会让一个人变成工作区成员。

获取频道 ID：在 Slack 中打开该频道，点击频道名称，在弹出面板底部复制 **Channel ID**。

移出成员大约 30 秒内生效。设置策略前请先把 Bot 邀请进该频道：它无法读取自己不在其中的频道，此时请求会被拒绝。

<Callout type="warning">
该频道必须是**私有**的。公开频道任何人都能加入，等于任何人都能给自己授权。Multica 会主动校验，而不是依赖设置本身：保存策略时会拒绝公开频道，并且每次刷新名单时都会重新校验——因此把频道改为公开后，Bot 会立即关闭，而不是悄悄扩大服务范围。
</Callout>

读取该频道需要 `groups:read` Bot scope。如果无法访问 Slack，Bot 会继续使用最后一次读到的成员列表，最长 15 分钟，避免一次故障让它彻底失声。过期的名单只能让原本就在名单上的人继续使用，不会放进任何新的人，因此故障只会推迟一次移出，而不会授予权限。超过 15 分钟后，它不再猜测，直接关闭。频道变为公开、或 Bot 被移出频道，都不属于故障，不享有任何宽限。

<Callout type="warning">
校验群聊需要读取其参与者列表，这依赖 `mpim:read` Bot scope。缺少该权限时无法读取列表，设为 `members_only` 的 Bot 会关闭全部群聊，而不会去猜测。依赖群聊前，请在 manifest 中加入该 scope 并重新安装 app。
</Callout>

## 管理连接

打开 **设置 → 集成** 可以查看所有已连接的 Slack Bot。工作区 owner 和 admin 可以断开连接。

断开后，Socket Mode 连接会停止，Bot 不再接收新消息。已有的对话和审计记录不会随之删除。

## 自托管配置

Multica Cloud 无需额外配置。自托管部署需要先设置一个用于加密 Slack token 的密钥：

```dotenv
MULTICA_SLACK_SECRET_KEY=<base64 编码的 32 字节密钥>
```

可以这样生成：

```bash
openssl rand -base64 32
```

重启 API 服务后，再连接 Slack app。该密钥需要长期保存：更换或丢失后，已有 token 无法解密，需要重新连接。

账号绑定链接使用 `MULTICA_APP_URL`，未设置时回退到 `FRONTEND_ORIGIN`；它需要指向成员可以访问的 Multica 地址。

## 常见问题

- **连接时提示 token 无效**：检查前缀，并确认两个 token 来自同一个 app。
- **无法验证 app**：确认 manifest 包含 `users:read`，更新权限后重新安装 app。
- **私聊没有入口**：确认 `app_home.messages_tab_enabled` 为 `true`。
- **频道里没有回复**：确认 Bot 已被邀请进频道，并在消息中 @ 了它。如果该安装启用了 `members_only`，还要确认频道 ID 在允许频道列表中。
- **提示 "Not available in this channel"**：发送者已授权，但该会话未授权。把频道 ID 加入这个安装的允许频道列表，或改用私聊。
- **群聊突然不工作了**：在 `members_only` 下，每一位参与者都必须是已绑定的工作区成员，并且 app 需要 `mpim:read`。添加该 scope 后需重新安装。
- **设置 `auth_channel_id` 后所有人都被拒绝**：确认 Bot 仍在该频道中，且该频道仍然是私有的。这两项会被持续校验，任何一项不满足都会让 Bot 关闭。
- **`/issue` 不存在**：确认 manifest 包含 slash command 和 `commands` scope，随后重新安装 app。
- **文件没有送达智能体**：确认 manifest 里包含 `files:read`，并且在添加该权限后重新安装过应用，同时确认文件不超过 20 MiB。
- **Bot 不执行**：检查智能体是否已归档，以及它使用的[运行时](/daemon-runtimes)是否在线。
