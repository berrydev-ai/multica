Multica는 사용자가 직접 만든 Slack app을 사용합니다. 연결하면 팀 멤버가 Bot과 DM을 나누고 채널에서 @멘션하거나 `/issue`로 이슈를 만들 수 있습니다.

Slack app 하나는 Multica 에이전트 하나에 대응합니다. 여러 에이전트를 연결하려면 에이전트마다 별도의 app을 만드세요.

## 시작하기 전에

연결은 워크스페이스 owner 또는 admin이 완료해야 하며 마지막에 두 자격 증명을 Multica에 입력합니다.

- `xoxb-`로 시작하는 Bot User OAuth Token
- `xapp-`로 시작하는 App-level Token

## 1. manifest에서 Slack app 만들기

[Slack API Apps](https://api.slack.com/apps)를 열고 **Create New App → From a manifest**를 클릭한 뒤 Slack workspace를 선택하고 **YAML**에 다음 내용을 붙여 넣습니다.

```yaml
display_information:
  name: Multica
features:
  app_home:
    home_tab_enabled: false
    messages_tab_enabled: true
    messages_tab_read_only_enabled: false
  bot_user:
    display_name: Multica
    always_online: true
  slash_commands:
    - command: /issue
      description: Create a Multica issue
      usage_hint: "[description]"
oauth_config:
  scopes:
    bot:
      - app_mentions:read
      - channels:history
      - files:read
      - groups:history
      - im:history
      - mpim:history
      - chat:write
      - reactions:write
      - users:read
      - commands
settings:
  event_subscriptions:
    bot_events:
      - app_mention
      - message.im
      - message.channels
      - message.groups
      - message.mpim
  interactivity:
    is_enabled: false
  org_deploy_enabled: false
  socket_mode_enabled: true
  token_rotation_enabled: false
```

만들기 전에 두 `Multica` 값을 에이전트 이름으로 바꿀 수 있습니다. manifest의 권한이나 이벤트를 삭제하지 마세요. 삭제하면 DM, 채널 멘션, 답글, `/issue`가 작동하지 않을 수 있습니다.

<Callout type="warning">
첨부 파일 지원이 추가되기 전에 이 Slack app을 설치했다면 Bot scope에 `files:read`를 추가하고 workspace에 app을 다시 설치하세요. app을 다시 설치하기 전에는 새 scope가 기존 Bot token에 적용되지 않습니다.
</Callout>

Bot은 Socket Mode로 Slack에 능동적으로 연결하므로 공개 Request URL이나 OAuth Redirect URL을 설정할 필요가 없습니다.

## 2. 두 token 받기

### Bot token

1. Slack app에서 **Install App**을 엽니다.
2. **Install to Workspace**를 클릭하고 권한을 승인합니다.
3. `xoxb-`로 시작하는 **Bot User OAuth Token**을 복사합니다.

### App-level token

1. **Basic Information → App-Level Tokens**를 엽니다.
2. **Generate Token and Scopes**를 클릭합니다.
3. `connections:write` scope를 추가합니다.
4. `xapp-`로 시작하는 token을 생성하고 복사합니다.

## 3. 에이전트에 연결

1. Multica에서 **에이전트**를 열고 Slack에 연결할 에이전트를 선택합니다.
2. **연동**으로 이동해 **Slack 연결**을 클릭합니다.
3. Bot token과 App-level token을 입력합니다.
4. **연결**을 클릭합니다.

Multica가 두 token이 같은 app에서 발급되었는지 확인합니다. 연결에 성공하면 페이지에 **Slack에 연결됨**이 표시됩니다.

<Callout type="warning">
두 token은 Multica 서버에 암호화되어 저장됩니다. Token은 자격 증명이므로 이슈, 댓글, 코드 저장소에 넣지 마세요. 이미 다른 에이전트나 워크스페이스에 연결된 app은 바로 재사용할 수 없으며 기존 연결을 먼저 해제해야 합니다.
</Callout>

## 처음 사용

멤버가 처음으로 Bot과 DM을 나누거나 @멘션하면 계정 연결 링크를 받습니다. 해당 워크스페이스의 Multica 계정으로 로그인한 뒤 Slack으로 돌아가 메시지를 다시 보내세요.

채널과 그룹 대화에서는 이 링크가 본인에게만 보이는 방식으로 전달되며, 대화에는 아무것도 남지 않습니다. Multica 워크스페이스 멤버가 아닌 사람도 링크를 받을 수는 있지만 연결을 완료할 수 없습니다. Bot은 같은 사람에게 하루 한 번까지만 응답합니다.

링크는 한 번만 사용할 수 있고 15분 뒤 만료됩니다. 만료되면 Bot에 메시지를 하나 더 보내 새 링크를 받으면 됩니다. 같은 Multica 워크스페이스의 여러 Bot이 같은 Slack workspace에서 만들어졌다면 기존 연결을 보통 재사용할 수 있습니다.

현재 Multica 워크스페이스의 멤버만 Bot을 사용할 수 있습니다.

## Slack에서 작업 요청

### DM

Slack 사이드바의 **Apps**에서 Bot을 열고 바로 메시지를 보냅니다. @멘션은 필요 없습니다.

### 채널과 그룹 채팅

먼저 `/invite @your-bot`을 실행해 Bot을 채널에 추가하고 `@your-bot 요청 내용`을 보냅니다. 각 thread는 독립된 대화가 됩니다. 후속 질문은 원래 thread에서 Bot을 계속 @멘션하세요.

Bot은 자신을 명시적으로 @멘션한 채널 메시지에만 응답합니다. 실행할 때 권한 범위 안에서 해당 thread의 최근 컨텍스트를 읽습니다.

### 파일 보내기

DM이나 Bot을 @멘션한 채널 메시지에 파일을 그대로 첨부하세요. 파일은 같은 작업의 첨부 파일로 전달되므로 에이전트가 요청 내용과 함께 읽을 수 있습니다.

이 기능에는 `files:read` scope가 필요합니다. 첨부 파일 지원 이전에 설치한 app이라면 1단계의 안내를 참고하세요. 파일 하나는 20 MiB 이하여야 하고 메시지 하나에 최대 10개까지 담깁니다. 용량을 초과했거나 아직 업로드 중이거나 Slack 외부에 있는 파일(예: Google Drive, Dropbox 링크)은 건너뛰며, 메시지 본문은 그대로 에이전트에 전달됩니다.

### `/issue`로 이슈 만들기

채널이나 DM에서 다음을 입력합니다.

```text
/issue Safari에서 로그인에 성공해도 로그인 페이지에 계속 머뭅니다.
```

이 명령에는 Bot @멘션이 필요 없습니다. Multica가 설명을 현재 Bot에 연결된 에이전트로 보내고 에이전트가 제목과 본문을 정리해 이슈를 만듭니다. Slack에는 먼저 나에게만 보이는 접수 메시지가 표시되며 생성이 끝나면 Multica 인박스에 알림이 도착합니다.

## Bot이 응답할 사람과 장소 제한

기본적으로 보낸 사람이 계정을 연결했고 해당 Multica 워크스페이스의 멤버라면, Bot은 초대된 모든 대화에서 응답합니다. 대부분의 팀에는 이것으로 충분합니다. 외부 사람이 Bot에게 말을 걸 수는 있어도 결과물은 얻지 못합니다.

Bot의 답변 자체가 민감한 경우에는 충분하지 않습니다. Bot이 하는 말은 그 대화에 있는 모든 사람에게 보이므로, 인원이 많은 채널에서 또는 게스트 한 명이 섞인 그룹 대화에서 승인된 멤버에게 답하면 그 답변이 전원에게 공개됩니다.

설치의 chat gate를 `members_only`로 설정하면 보낸 사람뿐 아니라 대화 자체도 검증합니다.

두 목록은 서로 다른 질문에 답하며 겹치지 않습니다. `auth_channel_id`는 **누가** Bot을 쓸 수 있는지를, `allowed_channel_ids`는 Bot이 **어디서** 일하는지를 정합니다. 명단을 가지고 있다고 해서 그 채널이 Bot이 응답하는 장소가 되지는 않습니다. 그곳에서도 Bot과 대화하려면 양쪽에 모두 등록하세요.

| 대화 종류 | 응답 조건 |
| --- | --- |
| DM | 보낸 사람이 계정을 연결했고 여전히 워크스페이스 멤버일 것. |
| 그룹 대화 (여러 명 DM) | Bot을 제외한 모든 참여자가 계정을 연결했고 여전히 워크스페이스 멤버일 것. 외부 사람이 한 명이라도 있으면 보낸 사람이 승인되었더라도 대화 전체를 닫습니다. |
| 채널 | 보낸 사람이 승인되었고, **동시에** 해당 채널 ID가 설치의 허용 채널 목록에 있을 것. |

닫힌 대화에는 멤버 조회 한 번 외에 아무 비용도 들지 않습니다. 세션도, 에이전트 실행도, 모델 사용량도 발생하지 않습니다. 보낸 사람에게만 여기서는 사용할 수 없다고 알리고, 다른 사람에게는 아무것도 보이지 않습니다.

설정 방법:

```http
PUT /api/workspaces/{workspace_id}/slack/installations/{installation_id}/access
```

```json
{
  "chat_gate": "members_only",
  "auth_channel_id": "G0123456789",
  "refusal_text": "Not an authorized operator",
  "allowed_channel_ids": ["C0123456789"]
}
```

명단에 없는 사람은 어디에서 말하든 본인에게만 그 사실이 전달됩니다. `refusal_text`로 문구를 직접 정할 수 있고, 비워 두면 일부러 아무것도 알려주지 않는 기본 문구가 쓰입니다. 명단에는 있지만 Bot이 일하지 않는 채널에서 말한 사람에게는 장소를 알려 주는 다른 문구가 가므로, 권한을 요청하는 대신 자리를 옮기면 된다는 것을 알 수 있습니다.

워크스페이스 owner와 admin만 호출할 수 있습니다. 본문은 **전체** 정책을 나타냅니다. 필드를 생략하면 이전 값이 남는 것이 아니라 그 설정이 지워집니다. 현재 정책은 `GET /slack/installations`의 각 설치에도 함께 반환됩니다.

`allowed_channel_ids`를 생략하면 Bot은 DM과 승인된 그룹 대화에서만 사용할 수 있습니다. 채널 ID는 대소문자를 구분합니다.

### Slack 채널을 명단으로 사용하기

`auth_channel_id`를 지정하면 비공개 Slack 채널의 멤버가 그대로 승인 명단이 됩니다. 권한을 주려면 그 채널로 초대하고, 회수하려면 내보내면 됩니다. 파일을 고치거나 다시 배포할 필요가 없고, 명단은 Slack 안에서 운영하는 사람에게 그대로 보입니다.

이 채널은 기존 조건을 좁히기만 하고 넓히지 않습니다. 사용자는 여전히 Slack 계정을 연결했고 해당 Multica 워크스페이스의 멤버여야 하며, 채널은 그 멤버 중 누가 대상인지만 결정합니다. 채널에 있다고 해서 워크스페이스 멤버가 되지는 않습니다.

ID는 Slack에서 채널을 열고 채널 이름을 클릭한 뒤, 대화 상자 아래쪽의 **Channel ID**를 복사하면 됩니다.

내보내기는 약 30초 안에 반영됩니다. 정책을 설정하기 전에 Bot을 그 채널로 초대하세요. 참여하지 않은 채널은 읽을 수 없어 요청이 거부됩니다.

<Callout type="warning">
채널은 반드시 **비공개**여야 합니다. 공개 채널은 누구나 들어올 수 있으므로 누구나 스스로를 승인할 수 있게 됩니다. Multica는 설정을 믿지 않고 직접 확인합니다. 정책을 저장할 때 공개 채널을 거부하고, 명단을 갱신할 때마다 다시 확인합니다. 따라서 나중에 채널을 공개로 바꾸면 대상이 조용히 넓어지는 것이 아니라 Bot이 즉시 닫힙니다.
</Callout>

채널을 읽으려면 `groups:read` Bot scope가 필요합니다. Slack에 접근할 수 없으면 Bot은 마지막으로 읽은 멤버 목록을 최대 15분간 계속 사용해 장애로 완전히 침묵하는 일을 막습니다. 오래된 목록으로 할 수 있는 일은 이미 명단에 있던 사람의 사용을 이어가는 것뿐이며 새로운 사람은 들어오지 못합니다. 즉 장애는 회수를 늦출 뿐 권한을 주지 않습니다. 15분이 지나면 추측을 멈추고 닫습니다. 공개로 바뀐 채널이나 Bot이 내보내진 채널은 장애가 아니므로 유예가 전혀 없습니다.

<Callout type="warning">
그룹 대화를 검증하려면 참여자 목록을 읽어야 하며, 여기에는 `mpim:read` Bot scope가 필요합니다. 이 scope가 없으면 목록을 읽을 수 없어 `members_only`로 설정된 Bot은 추측하지 않고 모든 그룹 대화를 닫습니다. 그룹 대화를 사용하기 전에 manifest에 scope를 추가하고 app을 다시 설치하세요.
</Callout>

## 연결 관리

**설정 → 연동**에서 연결된 모든 Slack Bot을 확인할 수 있습니다. 워크스페이스 owner와 admin이 연결을 해제할 수 있습니다.

연결을 해제하면 Socket Mode 연결이 중지되고 Bot이 새 메시지를 받지 않습니다. 기존 대화와 감사 기록은 함께 삭제되지 않습니다.

## 자체 호스팅 설정

Multica Cloud에는 추가 설정이 필요 없습니다. 자체 호스팅 환경에서는 Slack token 암호화에 사용할 키를 먼저 설정해야 합니다.

```dotenv
MULTICA_SLACK_SECRET_KEY=<base64로 인코딩한 32바이트 키>
```

다음과 같이 생성할 수 있습니다.

```bash
openssl rand -base64 32
```

API 서비스를 다시 시작한 뒤 Slack app을 연결하세요. 이 키는 장기간 보관해야 합니다. 키를 바꾸거나 잃어버리면 기존 token을 복호화할 수 없으므로 다시 연결해야 합니다.

계정 연결 링크는 `MULTICA_APP_URL`을 사용하고, 설정되지 않으면 `FRONTEND_ORIGIN`을 사용합니다. 멤버가 접근할 수 있는 Multica 주소를 지정해야 합니다.

## 자주 묻는 문제

- **연결할 때 token이 유효하지 않다고 표시됨**: 접두사를 확인하고 두 token이 같은 app에서 발급되었는지 확인합니다.
- **app을 확인할 수 없음**: manifest에 `users:read`가 포함되어 있는지 확인하고 권한을 업데이트한 뒤 app을 다시 설치합니다.
- **DM 메뉴가 없음**: `app_home.messages_tab_enabled`가 `true`인지 확인합니다.
- **채널에서 답변이 없음**: Bot이 채널에 초대되었고 메시지에서 @멘션했는지 확인합니다. 설치가 `members_only`를 사용한다면 채널 ID가 허용 채널 목록에 있는지도 확인합니다.
- **"Not available in this channel"이 표시됨**: 보낸 사람은 승인되었지만 그 대화가 승인되지 않은 상태입니다. 채널 ID를 설치의 허용 채널 목록에 추가하거나 DM으로 요청하세요.
- **그룹 대화가 갑자기 동작하지 않음**: `members_only`에서는 모든 참여자가 계정을 연결한 워크스페이스 멤버여야 하고, app에는 `mpim:read`가 필요합니다. scope를 추가한 뒤 다시 설치하세요.
- **`auth_channel_id`를 설정한 뒤 모두 거부됨**: Bot이 아직 그 채널에 있는지, 채널이 아직 비공개인지 확인하세요. 두 가지 모두 계속 재확인되며, 하나라도 어긋나면 Bot이 닫힙니다.
- **`/issue`가 없음**: manifest에 slash command와 `commands` scope가 포함되어 있는지 확인하고 app을 다시 설치합니다.
- **파일이 에이전트에 도착하지 않음**: manifest에 `files:read`가 포함되어 있는지, scope를 추가한 뒤 app을 다시 설치했는지 확인하고, 파일이 20 MiB 이하인지도 확인합니다.
- **Bot이 실행되지 않음**: 에이전트가 보관 처리되었는지, 사용하는 [런타임](/daemon-runtimes)이 온라인인지 확인합니다.
