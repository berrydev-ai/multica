Multica では、自分で作成した Slack app を使います。接続すると、チームメンバーは Bot へ DM を送る、チャンネルで @メンションする、`/issue` でイシューを作成するといった操作ができます。

1 つの Slack app に接続できる Multica エージェントは 1 つです。複数のエージェントを接続する場合は、エージェントごとに app を作成してください。

## 始める前に

接続はワークスペースの owner または admin が行います。最終的に次の 2 つの認証情報を Multica へ入力します。

- `xoxb-` で始まる Bot User OAuth Token
- `xapp-` で始まる App-level Token

## 1. manifest から Slack app を作成する

[Slack API Apps](https://api.slack.com/apps) を開き、**Create New App → From a manifest** をクリックして Slack workspace を選びます。次の内容を **YAML** に貼り付けてください。

```yaml
display_information:
  name: Multica
features:
  app_home:
    home_tab_enabled: false
    messages_tab_enabled: true
    messages_tab_read_only_enabled: false
  bot_user:
    display_name: Multica
    always_online: true
  slash_commands:
    - command: /issue
      description: Create a Multica issue
      usage_hint: "[description]"
oauth_config:
  scopes:
    bot:
      - app_mentions:read
      - channels:history
      - files:read
      - groups:history
      - im:history
      - mpim:history
      - chat:write
      - reactions:write
      - users:read
      - commands
settings:
  event_subscriptions:
    bot_events:
      - app_mention
      - message.im
      - message.channels
      - message.groups
      - message.mpim
  interactivity:
    is_enabled: false
  org_deploy_enabled: false
  socket_mode_enabled: true
  token_rotation_enabled: false
```

作成前に、2 か所の `Multica` をエージェント名に変更してもかまいません。manifest の権限やイベントは削除しないでください。削除すると、DM、チャンネルでのメンション、返信、`/issue` が動作しないことがあります。

<Callout type="warning">
添付ファイル対応が追加される前にこの Slack app をインストールしていた場合は、Bot scope に `files:read` を追加し、workspace に app を再インストールしてください。app を再インストールするまで、新しい scope は既存の Bot token に反映されません。
</Callout>

Bot は Socket Mode で Slack へ接続するため、公開 Request URL や OAuth Redirect URL の設定は不要です。

## 2. 2 つの token を取得する

### Bot token

1. Slack app で **Install App** を開きます。
2. **Install to Workspace** をクリックし、権限を承認します。
3. `xoxb-` で始まる **Bot User OAuth Token** をコピーします。

### App-level token

1. **Basic Information → App-Level Tokens** を開きます。
2. **Generate Token and Scopes** をクリックします。
3. `connections:write` scope を追加します。
4. token を生成し、`xapp-` で始まる値をコピーします。

## 3. エージェントへ接続する

1. Multica で**エージェント**を開き、Slack に接続するエージェントを選びます。
2. **連携**を開き、**Slack に接続**をクリックします。
3. Bot token と App-level token を入力します。
4. **接続**をクリックします。

Multica は 2 つの token が同じ app のものか確認します。接続に成功すると、画面に **Slack に接続済み**と表示されます。

<Callout type="warning">
2 つの token は暗号化して Multica サーバーに保存されます。Token は認証情報です。イシュー、コメント、コードリポジトリには書き込まないでください。ほかのエージェントやワークスペースに接続済みの app をそのまま再利用することはできません。先に元の接続を解除してください。
</Callout>

## 初回利用

メンバーが初めて Bot に DM を送るか @メンションすると、アカウント連携用のリンクが届きます。そのワークスペースで使う Multica アカウントにログインしてから、Slack に戻ってもう一度メッセージを送ってください。

チャンネルとグループでは、このリンクは本人にだけ表示される形で送られます。会話には何も残りません。Multica ワークスペースのメンバーでない人もリンクを受け取れますが、連携は完了できません。Bot が同じ人に応答するのは 1 日 1 回までです。

リンクは 1 回だけ使用でき、15 分後に期限切れになります。期限が切れた場合は、Bot にもう一度メッセージを送ると新しいリンクが届きます。同じ Multica ワークスペースにある複数の Bot が同じ Slack workspace のものなら、通常は既存のアカウント連携を再利用できます。

Bot を利用できるのは、現在の Multica ワークスペースのメンバーだけです。

## Slack から仕事を依頼する

### DM

Slack サイドバーの **Apps** から Bot を開き、そのままメッセージを送ります。@メンションは不要です。

### チャンネルとグループ

まず `/invite @your-bot` を実行して Bot をチャンネルに追加し、`@your-bot 依頼内容` を送ります。スレッドごとに独立したセッションが作られます。追加の依頼も、同じスレッドで Bot を @メンションしてください。

Bot が応答するのは、明示的に @メンションされたチャンネルメッセージだけです。実行時には、権限の範囲内でそのスレッドの直近のコンテキストを読み取ります。

### ファイルを送る

DM、または Bot を @ メンションしたチャンネルのメッセージに、そのままファイルを添付します。ファイルは同じ作業の添付ファイルとして届くので、エージェントは依頼内容と合わせて読み取れます。

これには `files:read` scope が必要です。添付ファイル対応より前にインストールした app の場合は、手順 1 の注意書きを参照してください。1 ファイルあたり 20 MiB 以下、1 メッセージにつき最大 10 件です。サイズ超過、アップロード処理中、または Slack 以外（Google Drive や Dropbox のリンクなど）にあるファイルはスキップされますが、メッセージ本文はエージェントに渡ります。

### `/issue` でイシューを作成する

チャンネルまたは DM で、次のように入力します。

```text
/issue Safari ではログインに成功してもログイン画面に残る
```

このコマンドでは Bot の @メンションは不要です。Multica は説明を現在の Bot に対応するエージェントへ渡し、エージェントがタイトルと本文を整理してイシューを作成します。Slack には最初に自分だけが見える受付メッセージが表示されます。作成が完了すると、Multica のインボックスに通知が届きます。

## Bot が応じる相手と場所を制限する

既定では、送信者がアカウントを連携済みで、その Multica ワークスペースのメンバーであれば、Bot は招待されたあらゆる会話で応じます。多くのチームにはこれで十分です。社外の人が Bot に話しかけることはできても、成果物は得られません。

ただし Bot の回答自体が機密を含む場合、これでは足りません。Bot の発言はその会話にいる全員に見えるため、大人数のチャンネルで、あるいはゲストが 1 人混じったグループで承認済みメンバーに返信すれば、その回答は全員に公開されます。

インストールの chat gate を `members_only` にすると、送信者だけでなく会話そのものも検証されます。

2 つのリストは別々の問いに答えるもので、重なりません。`auth_channel_id` は**誰が**Bot を使えるかを、`allowed_channel_ids` は Bot が**どこで**働くかを決めます。名簿を持っていることが、そのチャンネルで Bot が応答する理由にはなりません。そこでも Bot と話したい場合は、両方に登録してください。

| 会話の種類 | 応じる条件 |
| --- | --- |
| DM | 送信者が連携済みで、現在もワークスペースのメンバーであること。 |
| グループ (複数人 DM) | Bot 以外の参加者全員が連携済みで、現在もワークスペースのメンバーであること。部外者が 1 人でもいれば、送信者が承認済みでも会話全体を閉じます。 |
| チャンネル | 送信者が承認済みで、**かつ**そのチャンネル ID がインストールの許可チャンネル一覧にあること。 |

閉じた会話にかかるのはメンバー照会 1 回だけです。セッションもエージェントの実行もモデル利用も発生しません。送信者にはここでは利用できないことが本人にだけ伝わり、ほかの人には何も見えません。

設定方法:

```http
PUT /api/workspaces/{workspace_id}/slack/installations/{installation_id}/access
```

```json
{
  "chat_gate": "members_only",
  "auth_channel_id": "G0123456789",
  "refusal_text": "Not an authorized operator",
  "allowed_channel_ids": ["C0123456789"]
}
```

名簿にない人には、どこで書いても本人だけにその旨が伝わります。`refusal_text` で自分の言葉に置き換えられますし、省略すればあえて何も明かさない既定の文言が使われます。名簿にはいるが Bot が働いていないチャンネルで書いた人には、場所を示す別の文言が返るので、権限を求めるのではなく場所を変えればよいと分かります。

ワークスペースの owner と admin のみ実行できます。ボディは**完全な**ポリシーを表します。フィールドを省略すると前の値が残るのではなく、その設定が消えます。現在のポリシーは `GET /slack/installations` の各インストールにも含まれます。

`allowed_channel_ids` を省略すると、Bot は DM と承認済みグループでのみ利用できます。チャンネル ID は大文字と小文字を区別します。

### Slack チャンネルを名簿として使う

`auth_channel_id` を指定すると、プライベート Slack チャンネルのメンバーがそのまま承認名簿になります。権限を与えるにはそのチャンネルに招待し、取り消すには外します。編集も再デプロイも不要で、名簿は運用する人が Slack 上でそのまま見られます。

このチャンネルは既存の条件を狭めるだけで、広げることはありません。利用者は依然として Slack アカウントを連携済みで、その Multica ワークスペースのメンバーである必要があります。チャンネルが決めるのは、そのメンバーのうち誰が対象かということだけです。チャンネルにいることがワークスペースのメンバー資格になるわけではありません。

ID は、Slack でチャンネルを開き、チャンネル名をクリックして、ダイアログ下部の **Channel ID** をコピーします。

メンバーを外すと約 30 秒で反映されます。ポリシーを設定する前に Bot をそのチャンネルへ招待してください。参加していないチャンネルは読めないため、その場合はリクエストが拒否されます。

<Callout type="warning">
チャンネルは**プライベート**でなければなりません。パブリックチャンネルは誰でも参加できるため、誰でも自分を承認できてしまいます。Multica は設定を信用せず自分で検証します。ポリシー保存時にパブリックチャンネルを拒否し、名簿を更新するたびに再確認します。したがって後からチャンネルをパブリックに変換すると、対象が静かに広がるのではなく、Bot はただちに閉じます。
</Callout>

チャンネルの読み取りには `groups:read` Bot scope が必要です。Slack に到達できない場合、Bot は最後に取得したメンバー一覧を最大 15 分間使い続け、障害でそのまま沈黙してしまうことを防ぎます。古い一覧でできるのは、すでに名簿にいた人の利用を続けさせることだけで、新しい人が入ることはありません。つまり障害は取り消しを遅らせるだけで、権限を与えはしません。15 分を過ぎると推測をやめ、閉じます。パブリックに変わったチャンネルや、Bot が外されたチャンネルは障害ではないので、猶予は一切ありません。

<Callout type="warning">
グループの検証には参加者一覧の読み取りが必要で、`mpim:read` Bot scope に依存します。この scope がないと一覧を読めないため、`members_only` の Bot は推測せずにすべてのグループを閉じます。グループを利用する前に manifest へ scope を追加し、app を再インストールしてください。
</Callout>

## 接続を管理する

**設定 → 連携**を開くと、接続済みの Slack Bot をすべて確認できます。ワークスペースの owner と admin は接続を解除できます。

接続を解除すると Socket Mode の接続が停止し、Bot は新しいメッセージを受信しなくなります。既存の会話と監査記録は削除されません。

## セルフホスト設定

Multica Cloud では追加設定は不要です。セルフホスト環境では、Slack token を暗号化するキーを先に設定してください。

```dotenv
MULTICA_SLACK_SECRET_KEY=<base64-encoded 32-byte key>
```

次のコマンドで生成できます。

```bash
openssl rand -base64 32
```

API サービスを再起動してから Slack app を接続します。このキーは継続して保管してください。変更または紛失すると既存の token を復号できなくなり、app の再接続が必要になります。

アカウント連携用リンクには `MULTICA_APP_URL` が使われ、未設定の場合は `FRONTEND_ORIGIN` にフォールバックします。メンバーがアクセスできる Multica のアドレスを指定してください。

## よくある問題

- **接続時に token が無効と表示される**: 接頭辞を確認し、2 つの token が同じ app のものか確認します。
- **app を検証できない**: manifest に `users:read` が含まれていることを確認します。権限を更新した後は app を再インストールしてください。
- **DM の入口がない**: `app_home.messages_tab_enabled` が `true` であることを確認します。
- **チャンネルで返信がない**: Bot がチャンネルに招待されており、メッセージで @メンションされていることを確認します。インストールが `members_only` の場合は、チャンネル ID が許可チャンネル一覧にあることも確認します。
- **「Not available in this channel」と返る**: 送信者は承認済みですが、その会話が承認されていません。チャンネル ID をインストールの許可チャンネル一覧に追加するか、DM で依頼してください。
- **グループが急に使えなくなった**: `members_only` では参加者全員が連携済みのワークスペースメンバーである必要があり、app には `mpim:read` が必要です。scope を追加した後に再インストールしてください。
- **`auth_channel_id` を設定したら全員拒否される**: Bot がまだそのチャンネルにいること、チャンネルがまだプライベートであることを確認してください。どちらも継続的に再確認され、片方でも崩れると Bot は閉じます。
- **`/issue` がない**: manifest に slash command と `commands` scope が含まれていることを確認し、app を再インストールします。
- **ファイルがエージェントに届かない**: manifest に `files:read` が含まれていること、scope を追加した後に app を再インストールしたことを確認し、ファイルが 20 MiB 以下かも確認します。
- **Bot が実行しない**: エージェントがアーカイブされていないことと、使用する[ランタイム](/daemon-runtimes)がオンラインであることを確認します。
